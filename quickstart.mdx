## Prerequisites

Before you begin, make sure you have the following:

- **Node.js 18 or later** — the project targets ES2022 and uses Vite 7
- **npm**, **yarn**, or **pnpm** package manager
- **A running backend API** — all data fetching goes through `VITE_API_URL`. The frontend will not load any transactions, balances, or categories without it

<Note>
  The app is a pure frontend SPA. It has no built-in mock server. Every route in
  `src/api/transactions.ts` calls `${VITE_API_URL}/api/...`, so a real backend
  must be reachable before you open the app.
</Note>

## Setup

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone <your-repo-url> finance-app
    cd finance-app
    ```
  </Step>

  <Step title="Install dependencies">
    <CodeGroup>
      ```bash npm
      npm install
      ```

      ```bash yarn
      yarn install
      ```

      ```bash pnpm
      pnpm install
      ```
    </CodeGroup>
  </Step>

  <Step title="Set the API URL environment variable">
    Create a `.env` file in the project root and point `VITE_API_URL` at your
    backend:

    ```bash
    # .env
    VITE_API_URL=http://localhost:3000
    ```

    Vite only exposes variables prefixed with `VITE_` to the browser bundle.
    The value is read at build time via `import.meta.env.VITE_API_URL` in
    `src/api/transactions.ts`.

    <Warning>
      Never commit your `.env` file. Add it to `.gitignore` before your first
      commit.
    </Warning>
  </Step>

  <Step title="Start the development server">
    ```bash
    npm run dev
    ```

    Vite starts with `--host`, so the app is accessible on your local network
    as well as `http://localhost:5173`.
  </Step>
</Steps>

## First login

The app uses a lightweight client-side session — there are no server-side
accounts. On first load, `SettingsContext` checks `localStorage` for a saved
session under the key `user-login-finances`. If none is found, the router
redirects you to `/login`.

<Steps>
  <Step title="Enter a username">
    Type any non-empty display name into the username field on the login screen.
  </Step>

  <Step title="Pick an avatar">
    Choose one of the ten DiceBear avatars shown on the login page. The default
    is the green "Andrea" avatar. Your selection is stored alongside your
    username in the session.
  </Step>

  <Step title="Submit the form">
    Click the submit button. `saveUser()` writes
    `{ userName, userAvatar }` to `localStorage` under `user-login-finances`
    and navigates you to the dashboard at `/`.
  </Step>
</Steps>

<Tip>
  Your session persists across browser refreshes. To log out, use the logout
  option in the sidebar — it calls `setUser(null)`, which removes the
  `user-login-finances` key from `localStorage`.
</Tip>

## Available scripts

| Script | Command | Description |
|---|---|---|
| `dev` | `npm run dev` | Start Vite dev server with `--host` (LAN accessible) |
| `build` | `npm run build` | Type-check with `tsc -b`, then bundle with Vite |
| `preview` | `npm run preview` | Serve the production build locally |
| `lint` | `npm run lint` | Run ESLint across the project |

### Production build

```bash
npm run build
```

The build step runs `tsc -b` (composite project build using both
`tsconfig.app.json` and `tsconfig.node.json`) before invoking Vite, so any
TypeScript errors will fail the build.

```bash
npm run preview
```

Serves the contents of `dist/` locally so you can verify the production bundle
before deploying.
